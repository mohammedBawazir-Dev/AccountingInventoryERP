# نظام المحاسبة والمخزون – PHP + SQL Server

هذه حزمة موحّدة لمشروع `AccountingInventoryERP`، وتحتوي على نقطة تشغيل واحدة، اتصال SQL Server باستخدام PDO_SQLSRV، قراءة مخطط قاعدة البيانات تلقائيًا، وواجهات عربية RTL لإدارة شاشات النظام.

## 1) المتطلبات

- Windows مع XAMPP وApache.
- PHP 8.2 أو أحدث.
- امتداد `pdo_sqlsrv` مفعّل في نسخة PHP التي يستخدمها Apache.
- SQL Server شغّال وقاعدة البيانات `AccountingInventoryERP_DB` موجودة.
- صلاحية اتصال Windows/Integrated Authentication لمستخدم خدمة Apache أو إعداد SQL Login عند الحاجة.

## 2) تثبيت الملفات

1. فك ضغط المشروع.
2. انسخ مجلد `AccountingInventoryERP_Final` إلى:

   `C:\xampp\htdocs\AccountingInventoryERP`

3. إذا كان لديك مجلد مشروع قديم بهذا الاسم، خذ نسخة احتياطية منه أولًا. لا تدمج الملفات القديمة والجديدة عشوائيًا؛ استبدل مجلد المشروع بعد الاحتفاظ بنسختك الاحتياطية.
4. تأكد أن ترتيب الجذر كما يلي، وبالأخص أن `resources` بجانب `app` و`public` وليس داخل `public`:

```text
AccountingInventoryERP/
├── app/
├── config/
│   └── database.php
├── database/
├── docs/
├── public/
│   ├── assets/
│   ├── .htaccess
│   └── index.php
├── resources/
│   └── views/
└── .htaccess
```

## 3) إعداد الاتصال بقاعدة البيانات

افتح:

`C:\xampp\htdocs\AccountingInventoryERP\config\database.php`

الإعداد الافتراضي يستخدم نفس اسم الخادم وقاعدة البيانات اللذين نجحا في اختبار الاتصال السابق:

```php
return [
    'server' => '.',
    'database' => 'AccountingInventoryERP_DB',
    'username' => null,
    'password' => null,
    'encrypt' => 'yes',
    'trust_server_certificate' => 'yes',
];
```

إذا كان SQL Server مثبتًا كنسخة Express باسم `SQLEXPRESS` فغيّر `server` إلى `'.\\SQLEXPRESS'`. وإذا كنت تستخدم SQL Server Authentication، أدخل اسم المستخدم وكلمة المرور بدل `null`، وتأكد من تفعيل SQL Login ومنح الصلاحيات المناسبة.

## 4) التشغيل

1. شغّل Apache من XAMPP.
2. شغّل خدمة SQL Server.
3. افتح:

   `http://localhost/AccountingInventoryERP/`

4. من الشريط الجانبي افتح **فحص الاتصال** أو افتح مباشرة:

   `http://localhost/AccountingInventoryERP/?page=system_check`

5. بعد نجاح الاتصال افتح أي شاشة من القائمة. مثال دليل الحسابات:

   `http://localhost/AccountingInventoryERP/?page=chart_accounts`

> يمكن أيضًا فتح `http://localhost/AccountingInventoryERP/public/`، لكن الرابط الأول هو الرابط المختصر الموصى به.

## 5) حساب الدكتور وتسجيل الدخول وإدارة الصلاحيات

- الحساب الرئيسي المعتمد: `labeeb78@gmail.com`.
- يُنشأ جدول `dbo.AppUsers` وجدول `dbo.AppUserPermissions` تلقائيًا عند أول تشغيل إذا لم يكونا موجودين، مع ترقية جدول المستخدمين القديم بإضافة `IsSuperAdmin`.
- حساب الدكتور المحدد يُمنح صفة مدير النظام الأعلى تلقائيًا (`IsSuperAdmin = 1`) وتكون له جميع الصلاحيات، ولا يمكن تعطيله من شاشة إدارة المستخدمين.
- تسجيل الدخول يتطلب البريد الإلكتروني وكلمة المرور. كلمة المرور الأولية تُسلّم لصاحب المشروع خارج ملفات السورس. يطلب النظام تغييرها إجباريًا عند أول دخول.
- المدير يستطيع فتح **إدارة النظام ← المستخدمون والصلاحيات** لإضافة حسابات الموظفين، واختيار الدور الوظيفي كتصنيف، ثم ضبط صلاحيات العرض والإضافة والتعديل والحذف لكل شاشة بصورة مستقلة؛ الدور لا يمنح صلاحيات تلقائية.
- المستخدم الجديد لا يحصل على صلاحيات الشاشات تلقائيًا؛ يجب على المدير ضبطها. وتُحمّل التغييرات تلقائيًا في الطلب التالي للمستخدم.
- يمكن تعطيل الحسابات بدل حذفها للمحافظة على سجل المستخدمين.

> لا تستخدم تسجيل الدخول بالبريد وحده عند النشر العام. هذه النسخة تطلب كلمة مرور، وتخزّن تجزئتها باستخدام `password_hash` ولا تخزّن كلمة المرور الصريحة في قاعدة البيانات.

## 6) الشاشات الموجودة

تتضمن القائمة لوحة التحكم، العملات، الصناديق، البنوك، دليل الحسابات، الأرصدة الافتتاحية، الموردين، العملاء، الأصناف، الأنواع، الوحدات، المخازن، فواتير الشراء، فواتير البيع، قيود اليومية، سندات القبض، سندات الصرف، وحركات المخزون.

الشاشات مبنية على مخطط SQL Server الفعلي: تُقرأ أسماء الأعمدة والمفاتيح الأساسية والعلاقات الخارجية من قاعدة البيانات وقت التشغيل، ثم تُنشأ نماذج الإدخال والقوائم وفق الأعمدة الموجودة. تتوفر عمليات العرض والبحث والإضافة والتعديل والحذف، مع نماذج تفاصيل لفواتير الشراء والبيع وقيود اليومية وحركات المخزون عندما تكون جداول التفاصيل موجودة.

### خصائص مضافة

- واجهة عربية من اليمين إلى اليسار ومتجاوبة.
- حماية نماذج POST برمز CSRF.
- استعلامات PDO مُعلّمة بدل تركيب قيم المستخدم داخل SQL.
- اكتشاف المفاتيح الأجنبية وتكوين قوائم اختيار لها.
- دليل حسابات شجري مع فتح وإغلاق الفروع.
- الحساب الفرعي يرث مستوى الحساب ونوعه وطبيعته من الحساب الأب، مع منع تجاوز المستوى الخامس.
- حماية الحسابات النظامية والحسابات المشار إليها بمفاتيح خارجية من التعديل والحذف من شاشة دليل الحسابات.
- حساب إجمالي سطر تفاصيل الفاتورة (الكمية × السعر − الخصم) أو الحركة المخزنية (الكمية × تكلفة الوحدة) عند توفر الأعمدة المناسبة.
- طباعة القوائم من المتصفح.

## 7) ملاحظات مهمة حول قاعدة البيانات

يوجد في مجلد `database` ملف `repair_AccountingInventoryERP_DB_v4.sql`. هذا ملف إصلاح/استكمال للمخطط وليس ملف تشغيل تلقائي. **لا تشغله على قاعدة البيانات الحالية قبل أخذ Backup ومراجعة محتواه.** يحتوي على أوامر إعادة إنشاء جدولي `dbo.Stocks` و`dbo.Suppliers`، ويتوقف إذا وجد بيانات في أي منهما. لا حاجة لتشغيله إذا كانت قاعدة بياناتك الحالية مكتملة وتعمل كما هي.

## 8) ما الذي لا يجوز اعتباره مكتملًا بعد؟

الحزمة توفر واجهات تشغيل وإدارة عامة للجداول، لكنها ليست بعد نظام محاسبي إنتاجي مكتملًا. المستندات التي زودتني بها لا تحدد بعض قواعد العمل اللازمة، لذلك لم أضعها افتراضيًا ولم أنشئ نتائج محاسبية تخمينية. التفاصيل في `docs/KNOWN_LIMITATIONS.md`.

## 9) أين تبدأ عند تعديل الكود؟

- `public/index.php`: نقطة الدخول.
- `app/Core/Auth.php`: الحساب الرئيسي، المصادقة، الجلسات، والتحقق من الصلاحيات.
- `app/Controllers/UserController.php`: إدارة حسابات المستخدمين ومصفوفة الصلاحيات.
- `resources/views/users/`: شاشات المستخدمين والصلاحيات.
- `config/database.php`: إعدادات SQL Server.
- `app/Support/Modules.php`: أسماء الشاشات والجداول المرتبطة بها.
- `app/Core/SchemaInspector.php`: قراءة مخطط الجداول والعلاقات من SQL Server.
- `app/Core/CrudRepository.php`: عمليات CRUD والتحقق والحفظ.
- `app/Controllers/AppController.php`: توجيه طلبات الشاشات.
- `resources/views/`: واجهات العرض.
- `public/assets/app.css` و`public/assets/app.js`: التنسيق والتفاعلات.

## 10) فحص سريع قبل التسليم

راجع `docs/TEST_CHECKLIST.md` ونفّذ الاختبارات على نسخة احتياطية أو قاعدة اختبار قبل إدخال بيانات فعلية.

## 11) إعداد الاتصال عند الاستضافة

إعداد الاتصال المحلي الحالي يستخدم `.` واتصال Windows عند ترك اسم المستخدم وكلمة المرور فارغين. هذا لا يعمل من استضافة بعيدة. عند الاستضافة اضبط متغيرات البيئة التالية من لوحة مزود الاستضافة: `ERP_DB_SERVER`, `ERP_DB_NAME`, `ERP_DB_USERNAME`, `ERP_DB_PASSWORD`, `ERP_DB_ENCRYPT`, `ERP_DB_TRUST_CERT`. كما يجب أن تدعم الاستضافة امتداد PHP `pdo_sqlsrv` ومكتبات Microsoft ODBC Driver، وأن تسمح قاعدة SQL Server باتصالات خارجية آمنة. لا ترفع ملف قاعدة بيانات أو كلمة مرور إلى مستودع Git عام.
